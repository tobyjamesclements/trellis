# ADR-002: Grow-only, content-addressed fact log as the system of record; union is the merge

## Status
Accepted

## Context
DynamoDB Global Tables resolve concurrent writes to the same item by last-
writer-wins with no cross-region transactions, conditional writes or
uniqueness. Any mutable item written from two regions can lose an update
silently. The domain (formative learning) tolerates eventual consistency but
not silent loss of learner work.

## Decision
- The only authoritative data is a grow-only set of immutable facts.
- A fact's identity is the hash of its canonical encoding (`fact_id`), so
  the same fact written twice anywhere is the same item with the same
  meaning. Its DynamoDB key is `(subject, scope, writer_device, seq)`, which
  only its writer can produce.
- The merge of two replicas is set union. Convergence needs no
  coordination.
- Nothing mutable is stored where a fact can be appended instead: profile
  fields, enrolment, roles, structure, policies, keys, deadlines, marking,
  overrides, extensions, voids, side-effect ledgers are all facts.

## Consequences
- Storage grows monotonically (~3 GB/month per 10,000 active learners per
  region); this is cheap and exportable.
- Every consumer must be idempotent and tolerate out-of-order arrival.
- "Current value" is always a derivation (max by HLC, effective-fact rule).
- Erasure cannot delete meaning by deleting items; it destroys keys
  (ADR-007).

## Alternatives rejected
- CRDT state objects per entity (LWW-map, OR-set) stored as mutable items:
  requires the CRDT state itself to be merged, which LWW-per-item does not
  do; would need a custom merge on read and periodic write-back races.
- Single-region primary with read replicas: violates multi-active
  availability and the constraint.
