# ADR-016: No RDS, ElastiCache or OpenSearch; prebuilt search indexes and bounded derived indexes; Athena over S3 exports for ad-hoc analytics

## Status
Accepted

## Context
The constraint forbids these unless argued and costed. Search and ad-hoc
analytics are the usual reasons to want them.

## Decision
- **OpenSearch** rejected. OpenSearch Serverless has a floor of 2 OCUs
  (~$700/month) before any query; a provisioned t3.small domain is ~$30/month
  but single-AZ, single-region, and would hold a mutable index outside the
  fact model. Course content search is a prebuilt inverted-index blob per
  course rebuilt on publish (CAC), usable offline; forum search is a bounded
  per-(forum, cohort) trigram index in `derived` (COM). No cross-tenant or
  global search exists.
- **ElastiCache** rejected. Lambda in-memory caches (60 s TTL) plus DynamoDB
  reads at $0.125/M are cheaper than any cache cluster (≥ $12/month idle,
  VPC networking for Lambda, cold-start penalty inside a VPC).
- **RDS** rejected. No relational query in the design needs it; Aurora
  Serverless v2 has a 0.5 ACU floor (~$43/month) and is single-region-
  writer.
- **Athena** permitted for ad-hoc and research analytics over the Parquet
  fact exports (FLS-20): $5/TB scanned, no idle cost; at L10k a full-month
  scan costs about $0.02. It is never on a request path.

## Consequences
- Search quality is bounded (no fuzzy ranking beyond the client library).
- Analysts use SQL over exports, with decrypted exports gated by ADM-13.

## Alternatives rejected
- DynamoDB-backed inverted index for global search: hot partitions on
  common terms; scope creep.
