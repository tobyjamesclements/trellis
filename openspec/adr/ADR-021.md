# ADR-021: API edge: Route 53 latency routing with health checks to regional API Gateway HTTP APIs; CloudFront only for content

## Status
Accepted

## Context
Every region must serve every API; devices must reach the nearest healthy
region; the edge must cost nothing when idle.

## Decision
- Each tenant hostname is a Route 53 latency record set pointing at each
  region's API Gateway HTTP API regional endpoint with health checks;
  failover is DNS-driven (TTL 60 s).
- HTTP API (not REST API) for cost ($1/M) and built-in JWT authorizer.
- CloudFront fronts only S3 content (ADR-017), not APIs, to avoid
  double-hop latency and cost on the sync path.
- Callbacks that must land in an issuing region (auth, LTI) embed the
  region in `state` and redirect (IDE Tension 5, LTI-07).

## Consequences
- No usage plans on HTTP APIs; per-tenant rate limiting is WAF rate rules
  (optional, costed in ADM) or Lambda-side.
- Failover takes DNS TTL plus health-check interval (~1–2 min); devices
  retry transparently.

## Alternatives rejected
- CloudFront + Lambda Function URLs: cheapest, but no latency-based origin
  selection without Lambda@Edge, and weaker auth options.
- Global Accelerator: fixed hourly cost.
