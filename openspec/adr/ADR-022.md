# ADR-022: Encryption at rest with per-subject data keys under a zone KMS multi-Region key; plaintext metadata; server-side encryption on ingest

## Status
Accepted

## Context
Erasure by key destruction (ADR-007) requires per-subject keys; every
region must decrypt; KMS keys are regional unless multi-Region.

## Decision
- One KMS multi-Region key (MRK) per zone, replicated to each region of the
  zone. Per-tenant keys are an option costed in ADM-15 but not the default.
- Per-subject data keys generated with `GenerateDataKey`; ciphertext stored
  as immutable items `DK#<subject>#<dk_id>`; several may exist per subject;
  each fact records the `dk_id` used.
- Fact bodies are encrypted with AES-256-GCM by the ingest Lambda after
  hash verification; `fact_id` is over plaintext. Metadata needed for keys,
  routing, ordering and derivation selection stays plaintext.
- Plaintext data keys are cached in Lambda memory for ≤ 5 minutes.
- Signing keys (sessions, LTI, credentials) are asymmetric MRKs with `kid`
  registry facts.

## Consequences
- Ciphertext differs per region for the same fact; anti-entropy compares
  `fact_id`s, not bytes.
- KMS call volume is bounded by cache misses (~$5/month at L10k).
- Derived rows containing personal data are regenerable and not backed up;
  they are recomputed without the subject on erasure rather than encrypted.

## Alternatives rejected
- Client-side encryption with learner-held keys: instructors marking a
  learner's work would need key distribution; deferred.
- No encryption, physical deletion for erasure: leaves backups.
