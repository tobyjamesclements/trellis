# ADR-008: Hybrid logical clock stamping at sync; deadlines are advisory; work is never rejected

## Status
Accepted

## Context
Device clocks are untrusted; offline work arrives late; regions do not share
a clock. The product promise is that learner work is never lost.

## Decision
- Each fact carries the device's claimed `device_hlc` and the ingest
  region's `sync_hlc` (FLS-05). Device values never advance server clocks.
- Ordering for derivation is `(sync_hlc, fact_id)`.
- Deadlines are published facts; lateness is stamped at ingest as advisory
  and re-derived under policy (`arrival`, `claimed`, `grace(24h)` default)
  with extensions (DRV-07).
- No fact is rejected for lateness, duplication, over-cap or staleness.
  Rejections exist only for malformed, oversized, unauthorised-subject or
  seq-conflicting facts, and each tells the device how to repair.

## Consequences
- The envelope can differ between regions for the same fact (bounded by
  retry windows); it is never used as authority.
- Time limits on quizzes are advisory; the server flags, the client
  enforces for UX.

## Alternatives rejected
- Server-assigned global sequence: needs coordination.
- Rejecting late submissions: contradicts the product and creates data loss
  at the worst moment.
