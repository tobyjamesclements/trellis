# ADR-004: Derived state is regional, recomputable and never stored in a global table

## Status
Accepted

## Context
Views, rosters, indexes and Merkle summaries are functions of the fact set.
Replicating them would multiply write cost by the number of regions and
would put concurrently computed values under last-writer-wins.

## Decision
- Every region computes all derived state from its own replica, driven by
  its own DynamoDB stream, and stores it in a regional `derived` table with
  no replication and no backups.
- Derived items carry the version vector (or a digest of it) they were
  computed at, plus a generation for wholesale recomputes.
- Loss of a derived table is recovered by recompute from facts (MVA-12).
- Regions compare derived state only to make freshness statements (vector
  dominance, root digests), never to merge.

## Consequences
- Derivation compute runs N times (once per region). At L10k that is ~$20
  per month; at 1M learners ~$2,000, still far below the alternative of
  replicated view writes.
- Cross-region freshness comparison requires cross-region reads of headers,
  which is done on demand (MVA-11), not continuously.
- Stream semantics must include replicated writes (project.md A6), or a
  cross-region fan-out replaces them.

## Alternatives rejected
- Home-region derivation with replicated views: halves compute but doubles
  write cost and makes views unavailable during failover until recompute.
- Views in the global table keyed by region: no conflicts, but replication
  cost with no reader benefit.
