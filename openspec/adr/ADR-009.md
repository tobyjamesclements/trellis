# ADR-009: Numeric and uniqueness invariants are not enforced; overbook and reconcile with named apology workflows

## Status
Accepted

## Context
Global uniqueness and cross-region counters are unavailable. Enrolment
caps, seats, slots, one-submission-per-item, unique emails, single
issuance are all such invariants.

## Decision
- No invariant of this class is enforced at write time anywhere.
- Each has an owner spec, a reconciliation computed over the union, a
  deterministic order (`sync_hlc`, `fact_id`), a protection rule that never
  penalises a learner who has since acted, an instructor-in-the-loop step
  with a bounded wait (Step Functions Standard task token, default 24 h),
  and an apology communication with alternatives. See `tradeoffs.md`.
- Where an identifier must be unique, it is made deterministic (hash of its
  natural key) so concurrent minting yields the same value (principals for
  federated identities, LTI client and deployment ids, lineitems,
  credential ids, course ids for tool contexts).

## Consequences
- Instructors see "N over cap" instead of "enrolment closed".
- Some learners will be waitlisted after being admitted (soft-cap default
  minimises this).
- Product copy and support runbooks must explain each workflow.

## Alternatives rejected
- Home-region-only writes for capped operations: a global lock in disguise;
  unavailable during outages, which is when bursts happen.
- Regional seat shares as the default: complex UX; offered as an option.
