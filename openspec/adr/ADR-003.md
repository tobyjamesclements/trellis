# ADR-003: Global-table item discipline: every item is immutable or region-owned

## Status
Accepted

## Context
Last-writer-wins per item is safe only if two regions never write different
meanings to the same key.

## Decision
Every item in a global table falls into exactly one class:
1. **Immutable fact** (ADR-002): written once by its writer; identical
   plaintext on any re-put; only the ingest envelope and encryption IV may
   differ between regions and both are advisory.
2. **Region-owned**: the key contains the writing region (`LEDGER#<region>`,
   `DK#…#<dk_id minted in region>`, `KEYS#<kid minted in region>`); other
   regions read but never write it.
3. **Terminal**: an operator-only, idempotent, absorbing write (data-key
   deletion, fact shred, tenant deletion) that any region may apply and
   whose result is the same regardless of order; these are swept after the
   replication window.
Any design that needs a fourth class is wrong and must be re-expressed as
facts plus derivation.

## Consequences
- Counters, "current" pointers, membership lists and queues never live in
  the global table.
- Region-owned items require readers to consult every region's item (N
  reads) when a global answer is wanted (e.g. "was this side effect sent
  anywhere?").
- Reviews check every new global-table item against the three classes.

## Alternatives rejected
- Application-level vector clocks on mutable items with merge-on-read:
  possible, but every reader must merge and write back, reintroducing
  races; facts-plus-derivation is simpler and auditable.
